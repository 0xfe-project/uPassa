# tlispi —— nanopass-ts 的 tiny lisp

一个跑在 nanopass-ts 管线上的小 lisp。它是这个仓库的"给人看"的入口：喂一句话，能看到
它经过 14 个 pass 变成什么，以及跑出来的值。

```bash
pnpm e2e:tlispi              # 交互式
pnpm e2e:tlispi -e '(+ 1 2)' # 跑一次就退出
echo '(+ 1 2)' | pnpm e2e:tlispi   # 从管道读一整段
```

交互模式下：

| 命令     | 作用                                                           |
| -------- | -------------------------------------------------------------- |
| `:help`  | 帮助                                                           |
| `:all`   | 打开/关闭「每一步 pass」的显示（默认只显示每门语言的最后一步） |
| `:src`   | 显示当前累积的程序                                             |
| `:reset` | 清空累积的程序                                                 |
| `:q`     | 退出                                                           |

每喂一句会打印两样东西：

1. **每门语言的编译结果** —— 语言名（每门一个颜色）+ 是哪一步产出它的 + AST
2. **最后一条语句的值**（绿色）

出错时是红色，而且那句话**不会**加进累积的程序里（所以打错了不用担心污染后面）。

## 管线

```
Lnum → Lsrc → L1 → L2 → L3 → L4 → L5 → L6 → L7
```

| 语言   | 是哪一步之后           | 这一门的意义                                                                                                              |
| ------ | ---------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `Lnum` | （输入）               | 糖都在，而且**数字还没分种类**：只有一个笼统的 `Num { value, repr }`                                                      |
| `Lsrc` | `refine-repr`          | 数字细分成 `Int` / `Float`（按源码写法，`1` 是 Int、`1.0` 是 Float）                                                      |
| `L1`   | `desugar-def-fun`      | `(define (f x) e)` → `(define f (lambda (x) e))`                                                                          |
| `L2`   | `remove-when-unless`   | `when`/`unless` → `if`                                                                                                    |
| `L3`   | `remove-cond`          | `cond` → 右嵌套 `if`                                                                                                      |
| `L4`   | `remove-and-or-not`    | `and`/`or`/`not` → `if`（`or` 要一个临时变量，不然会重复求值）                                                            |
| `L5`   | `expand-let-star`      | `let*` → 嵌套 `let`                                                                                                       |
| `L6`   | `remove-one-armed-if`  | `(if c t)` → `(if c t (void))`                                                                                            |
| `L6`   | `normalize-begin`      | `(begin)` → `(void)`，`(begin e)` → `e`                                                                                   |
| `L6`   | `algebraic-simplify`   | 代数化简：`x*1`→`x`、`x*2`→`x+x`、`x+0`→`x`，`+`/`*` 按 AC 正规形**展平 + 排序**（`(+ (+ a b) (+ c d))` → `(+ a b c d)`） |
| `L6`   | `normalize-prim-arity` | `(+ a b c)` → `(+ (+ a b) c)`                                                                                             |
| `L6`   | `const-prop`           | 已知是字面量的变量引用，换成字面量                                                                                        |
| `L6`   | `constant-fold`        | `(+ 1 2)` → `3`，`(if #t a b)` → `a`（丢掉另一支）                                                                        |
| `L7`   | `uncover-free`         | 每个 lambda 挂上自己的自由变量（给以后的闭包转换用）                                                                      |
| `L7`   | `dce`                  | 没人用的 `let` 绑定删掉                                                                                                   |

为什么要有 `Lnum` 这一门：**"这是个整数"不是读进来的事实，是编译器的一个决定**。宿主里
`1` 和 `1.0` 都是同一个 number，读入器手里其实只有数字本身；它真正知道的是**字面量长什么样**
（`repr`）。所以读入器只写 `Num { value, repr }`，"这是 Int 还是 Float"由 `refine-repr`
在类型环境里决定 —— 而且那一步会做**提升**（一条算术里有 Float 就整条按 Float 算，
`(* 1.5 2)` 就是这样），也会在真正只收整数的地方（`modulo`）报错。

`Lsrc` 和 `L6` 之间的每一步只消一种糖 —— 这是 nanopass 的全部主张：一层语言只跟邻居差一件事。

## 语法

下面每条的例子都是**真的会跑**的（`pnpm e2e` 会拿这一节里的 `>` 行跑一遍，跟下一行对答案）。

### 字面量

```lisp
> 42
42

> -7
-7

> 3.5
3.5

> "hello"
"hello"

> #t
#t
```

整数和浮点是**两种东西**（`42` 是 Int，`3.5` 是 Float）。`(+ 1 2)` 得 Int，`(+ 1.5 2.5)` 得 Float ——
这条差别在 `constant-fold` 那一步要小心（不能把整数折成浮点，反过来也不行）。

### 算术与比较

`+ - * /` 都是 n 元的，`modulo` 是二元的。`<` 和 `=` 是**链式**的（`(< 1 2 3)` 意思是 `1<2 且 2<3`）。

```lisp
> (+ 1 2 3 4)
10

> (- 10 1 2)
7

> (- 5)
-5

> (* 2 3 4)
24

> (/ 12 4)
3

> (modulo 7 3)
1

> (< 1 2 3)
#t

> (= 1 1 1)
#t
```

### if / when / unless

`if` 可以只有一条臂 —— 那种情况下不成立时值是 `void`（打印成 `#<void>`）。

```lisp
> (if (< 1 2) 10 20)
10

> (if #t 1)
1

> (if #f 1)
#<void>

> (when #t 42)
42

> (unless #f 42)
42
```

`if` 和 `when`/`unless` 的条件**必须是 `#t`/`#f`** —— `(if 1 2 3)` 会报错，不是"1 算真"。

### cond

```lisp
> (cond [(< 3 2) "a"] [(= 1 1) "b"] [else "c"])
"b"

> (cond [(< 3 2) "a"] [else "c"])
"c"

> (cond [#f 1])
#<void>
```

### and / or / not

`and`/`or` 的操作数**必须是 `#t`/`#f`**，因为它们展开成 `if`，而 `if` 的条件收 bool。
（例外：`or` 的**最后一个**操作数不会被当条件测，所以可以是别的类型。）

```lisp
> (and #t #t)
#t

> (or #f #t)
#t

> (or #f #f "x")
"x"

> (not #f)
#t

> (and)
#t

> (or)
#f
```

### begin

```lisp
> (begin 1 2 3)
3
```

### let / let* / letrec

`let` 的绑定是**并行**的（绑定值看不见彼此），`let*` 是顺序的，`letrec` 能互相递归。

```lisp
> (let ((x 1) (y 2)) (+ x y))
3

> (let ((x 1)) (let ((x 2) (y x)) y))
1

> (let* ((x 1) (y (+ x 1)) (z (* y 10))) z)
20

> (letrec ((ev? (lambda (k) (if (= k 0) #t (od? (- k 1)))))
           (od? (lambda (k) (if (= k 0) #f (ev? (- k 1))))))
    (ev? 10))
#t
```

### lambda 与调用

```lisp
> ((lambda (x) (* x x)) 5)
25
```

```lisp
> (define double (lambda (x) (* x 2)))
> (double 21)
42
```

函数是闭包 —— 能捕获定义处的变量。

```lisp
> (define (adder n) (lambda (x) (+ x n)))
> ((adder 10) 5)
15
```

### define

两种写法都行：`(define (f x) e)` 和 `(define f e)`。

**定义要放在其它表达式前面** —— 但这说的是**一个程序**（一份源码）。REPL 里每次输入都是
一个独立的程序、共用一个环境，所以 `define` 随时可以写（下面第 2 句就是在用过之后才定义的）：

```lisp
> (+ 1 2)
3
> (define (sq x) (* x x))
> (sq 5)
25
```

这条区别是刻意的：`Program` 这个形状（`defs` 在前、`body` 在后）本身就把"一个程序"这件事
说清楚了；而"一次会话"是一串程序。前面那个例子里 `> ` 开头的每一行都是独立的一次输入。

```lisp
> (define (fact n) (if (< n 2) 1 (* n (fact (- n 1)))))
> (fact 6)
720
```

```lisp
> (define k 5)
> (+ k 1)
6
```

### 注释

`;` 到行尾。

```lisp
> (+ 1 2) ; 这是注释
3
```

## 会报错的东西

报错分三类，都是红色的。`:src` 能看到当前程序是什么。

**语法错误**（reader 就拦下）

```lisp
> (+ 1
语法错误 <repl>:1:1: 括号没闭合
```

**编译错误**（管线里某一步）

```lisp
> nope
运行期错误 未绑定的变量：nope
```

**运行期错误**

```lisp
> (1 2)
运行期错误 不是函数：1（在 Var 位置调用）
```

```lisp
> (if 1 2 3)
运行期错误 if 的条件必须是 bool，拿到 1
```

## 这个 lisp 的已知边界

诚实列一下，免得踩到以为是 bug：

| 边界                                                 | 说明                                                                                                                                                |
| ---------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `if`/`when`/`unless`/`and`/`or` 的条件只收 `#t`/`#f` | 没有"真值"概念。`(if 1 2 3)` 报错                                                                                                                   |
| `and`/`or` 的操作数只收 `#t`/`#f`                    | 因为展开成 `if`。例外：`or` 最后一个                                                                                                                |
| 没有 `set!`                                          | 所以 `dce` 删绑定不需要看副作用，`constant-fold` 敢丢死支                                                                                           |
| 没有 `let` 的"命名 let"、没有 `define` 的柯里化      | 这门语言很小                                                                                                                                        |
| 深度                                                 | 生成的遍历器是递归下树的，几千层嵌套就会报"嵌套太深"（明确的报错，不是栈溢出崩掉）。要更深可以用蹦床版的生成器（`fuseGroups` 的 `trampoline` 选项） |
| 变量名以 `$` 开头                                    | 是**保留前缀** —— `or` 展开时会造 `$or1` 这种临时名                                                                                                 |
| 浮点                                                 | 有，但 `Int`/`Float` 是分开的两种东西，不会隐式混                                                                                                   |
